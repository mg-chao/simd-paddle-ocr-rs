2026-11-24 在同一台 Windows 物理机上运行。128 张原图分别测试 tiny、small、medium。修改前有 **12/384** 个整图结果与 Python 逐行逐字完全一致，修改后为 **371/384**。原先一致的 12 个结果全部保持一致。三套 Python 参考、三套旧 Rust 输出和三套最终 Rust 输出均覆盖全部 128 张图，执行失败数均为零。

## 参考与修复

Python 从 `E:\RapidOCR\python` 的提交 `28490093dfb75dc4cd0f5d4f1d2259aeb44f5351` 导入，以 `RapidOCR(...)(image_path)` 运行。Python 3.12.10，ONNX Runtime 1.24.4，OpenCV 4.12.0，NumPy 2.2.6，Pillow 12.3.0。每个预设分别校验识别词表、权重、字典的完整 SHA-256 和实际 CPU provider，保存在 `reference/<preset>/config.json`。tiny 使用 `det.onnx`、`rec.onnx` 和 `ppocr_keys.txt`，small 与 medium 各用同名前缀的检测和识别模型，共用 `rec_keys.txt`。三组都使用 `cls.onnx`，实际分类输入为 3 × 80 × 160。Python 保持方向分类开启、旋转阈值 0.9、检测二值化阈值 0.3、框阈值 0.5、识别过滤阈值 0.5。参考配置还记录了缩放、膨胀、候选数量、扩框和批处理设置。

旧的本机采集脚本缺少独立的 medium 参考，且覆盖了分类、过滤和模型选择。此次以新的独立采集目录冻结参考。原图有 76 张 PNG、49 张 JPG 和 3 张 WebP，保留原始相对路径和 SHA-256。两端对三张 WebP 读取同一份无损 PNG。Rust 经公开 builder、默认 CPU 内核和 `ocr --json` 运行，采集时逐张校验 JSON 总文本与分行文本能重新拼合。比较工具先用三图自比较，并用有意更改的样例验证大小写、空格、标点和顺序计数。

- **输入与检测。** 对齐示例的 JPEG 解码、索引 PNG、方向和透明度处理，以及 OCR 工作图缩放、填充、检测归一化和原图坐标还原。DB 修正轮廓候选截断顺序、孔边界、整数填充、最小外接矩形和扩框取整。样本 78 有超过 1,000 个轮廓，候选截断顺序会改变实际保留的框。样本 122 的半像素扩框误差修复后，三个预设均整图一致。
- **裁剪与方向。** 对齐四点透视变换、1/32 像素插值相位和方向分类。medium 样本 6 在固定框条件下曾有 63 个通道字节相差 1，把当时的 Rust 识别张量交给 ORT 也会产生同一错字。修复采样后，该图 43 行全部一致。
- **识别与输出。** 公开默认入口按宽高比分组，每六个裁剪共享归一化宽度，对齐等宽高比的排序。在 medium 样本 98 上，等值裁剪的分组会改变识别画布。高层输出使用词表概率、逐字符及行分数取整、空白行和低分行过滤。低层仍可显式选择 logit 模式。裁剪相位、框取整、候选顺序、分组和 CTC 空白列均有小型回归用例。

## 性能

同一台 AMD Ryzen 9 5950X 工作站、同一张 764 × 950 RGB 图片 `009b147315000d75c16a87c0bc2814b1.png`、同为 8 个 CPU 线程、默认原生后端、release。计时从已加载模型的 `request.run` 开始，包含输出转为自有对象的时间。模型加载与图像解码在计时区间外。每个版本共 1 次预热，给 tiny；每个预设正式测 1 次。small 和 medium 测量已加载模型的首次请求。

| 预设 | 旧版 ms | 最终版 ms | 变化 |
| --- | ---: | ---: | ---: |
| tiny | 60.423 | 64.510 | +6.8% |
| small | 178.821 | 195.805 | +9.5% |
| medium | 657.296 | 685.656 | +4.3% |

三个预设在这张图上的单次观测均变慢。单样本、单次测量无法估计噪声区间或推断整库速度。另用带 profiling 的独立 release 对同图 small 各执行一次、零预热，以定位开销。

| small 分阶段墙钟（ms） | 基线 | 对齐后的中间版本 | 最终版本 |
| --- | ---: | ---: | ---: |
| 检测预处理 | 1.723 | 1.530 | 1.494 |
| 检测推理 | 93.435 | 94.793 | 93.902 |
| 检测后处理 | 1.458 | 1.643 | 1.703 |
| 裁剪 | 1.038 | 0.841 | 0.845 |
| 方向分类 | 2.540 | 2.465 | 2.491 |
| 识别 | 77.959 | 93.129 | 88.654 |
| 总计 | 178.673 | 194.972 | 189.635 |

增加的时间主要在识别阶段。高层默认处理完整词表概率及六图一组的画布。最终实现用 SIMD 筛出确定由 CTC 空白胜出的时间步，跳过其 Softmax，并复用行缓冲区。输出字符继续使用完整词表概率。中间和最终两次分阶段观测中，识别耗时相差 4.475 ms。
